# RFC 0001: Minimal Multi-agent Memory Layer

## Summary

Build the smallest useful memory layer for multi-agent collaboration before adding
review workflows, voting, or a public portal. The control plane remains
local-first; GitHub and misakanet.org are read-only export targets for sanitized
memory items.

The immediate pain from session history is that useful outputs are scattered
across local agents, private machines, cloud agents, review notes, roadmaps, and
front-end architecture discussions. The MVP should make each agent able to append
and search short, structured memory records without requiring network tunneling or
an always-available public service.

## Goals

- Provide a local HTTP API backed by SQLite for appending and reading memory.
- Keep sensitive/raw enterprise content local by default.
- Export only explicitly sanitized memory to repo files or a future portal.
- Make the exported format simple enough for GitHub-only agents to consume.
- Avoid a separate vector database, queue, auth system, or agent voting process in
  v0.

## Non-goals

- No multi-agent approval vote before implementation.
- No raw chat/session upload.
- No secret/token/local-path publication.
- No public write endpoint in v0.
- No internal network tunneling.
- No RAG/vector search in the first cut.

## MVP Architecture

```text
local agents
  Claude / Codex / other local runners
        |
        | POST /api/memory/items
        v
multi-agent-manager
  FastAPI + SQLite memory_items table
        |
        | scripts/export_memory.py
        v
repo ledger
  public/memory/items.jsonl
  public/memory/index.json
        |
        v
optional future portal
  misakanet.org/memory reads the same exported files
```

## Memory item model

A memory item is a small, explicit record. It is not a raw transcript.

Required fields:

- `id`: stable memory id, generated by the server when omitted.
- `type`: `review`, `roadmap`, `architecture`, `decision`, `session`, or
  `external`.
- `title`: one-line summary.
- `content`: sanitized markdown/plain text body.
- `source_node`: where it came from, for example `company-win`.
- `sensitivity`: publication boundary.
- `sync_status`: local/export state.
- `created_at`: timestamp.

Sensitivity levels:

- `public`: safe for repo and portal.
- `project-public`: safe for the public project, but not a generic blog post.
- `internal-summary`: sanitized enough for local/internal use, not exported by
  default.
- `private-local-only`: local machine only.
- `secret-never-sync`: must never leave local storage.

## API surface

Minimum API:

```text
POST /api/memory/items
GET  /api/memory/items?limit=50&q=roadmap
GET  /api/memory/items/{memory_id}
PATCH /api/memory/items/{memory_id}/sync-status
GET  /api/memory/public
```

Boundary rule:

- New items default to `private-local-only` and `local-only`.
- Only `public` and `project-public` items may be marked ready/synced for GitHub
  or portal export.
- Public export excludes everything else.

## Repo / portal export

The repo ledger is a static artifact, not a live coordination server:

```text
public/memory/items.jsonl
public/memory/index.json
```

`items.jsonl` is append/read friendly for agents. `index.json` gives counts,
last export time, and ids. A future misakanet.org page can read the same files
without adding a write endpoint.

## Minimal workflow

1. An agent finishes a useful task or review.
2. It writes a short memory item to the local API.
3. The item stays local by default.
4. A human/agent rewrites it as sanitized content if it should be shared.
5. The item is marked `ready-for-github`.
6. `scripts/export_memory.py` writes the public JSONL/index files.
7. The files are committed to GitHub or copied to the portal deploy pipeline.

## Acceptance criteria

- Local API can create and list memory items.
- Memory items can be searched by text query and filtered by source/type/status.
- Public export contains only `public` or `project-public` items with export-ready
  sync status.
- Export fails loudly on obvious tokens, local paths, or internal URLs.
- GitHub-only agents can read the exported JSONL without local API access.
